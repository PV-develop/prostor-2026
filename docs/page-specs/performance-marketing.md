### Ключевые ограничения по обещаниям (обязательны для всех текстов страницы)

Не обещать:

- гарантированные продажи;
- гарантированное количество лидов;
- фиксированную стоимость заявки или продажи без анализа проекта;
- быстрые результаты;
- скидки;
- универсальные сроки запуска, минимальные бюджеты и период окупаемости без привязки к продукту.

Позиционирование: построение управляемой системы и измеримость без безусловных обещаний. Обязательный следующий шаг — брифинг/консультация, после которой принимается решение о сотрудничестве. За агентством остаётся право отказаться от проекта.

## Визуальное направление

Визуальный редизайн не меняет карту блоков, тексты, URL, SEO, форму и контентные ограничения. Направление продолжает главную страницу и `reference/claude-design/`: строгая editorial-сетка, дисплейная типографика Steelfish, технические подписи JetBrains Mono, чёрный/светло-серый фон и красный только как функциональный акцент. Не использовать декоративные градиенты, скругления, тени, иконки и «маркетинговый глянец».

### Принципы композиции

- **Управляемый ритм.** На светлых внутренних страницах использовать уменьшенный вертикальный шаг секций вместо одинаковых больших пустот. Расстояние внутри блока зависит от его смысловой плотности: заголовок → данные → вывод/CTA. Воздух сохраняется между смысловыми группами, а не внутри строк без причины.
- **Разные форматы для разных данных.** Карточки применяются для самостоятельных сценариев и составляющих бюджета; нумерованные строки — для системы каналов; двухколоночная матрица — для связи «что выясняем → решение»; отдельные уровни — для метрик; таблица — для этапов процесса. Не сводить соседние секции к одному шаблону.
- **Контрастная типографика.** Основной текст на светлом — не ниже `--color-text-on-light-74`, ключевые названия — Steelfish, вторичные пояснения остаются читаемыми. Нумерация 01–05 задаёт навигационный ритм и не заменяет содержание. Reveal влияет только на появление, конечное состояние всегда полностью непрозрачное.
- **Плотные акценты.** Тёмная секция метрик разрывает монотонность светлой середины. Красный используется для номеров, коротких линий и CTA, а не как сплошная декоративная заливка больших областей.
- **Интегрированные действия.** CTA после сценариев и состава бюджета входит в завершающую панель соответствующего блока. В финальной форме аудит и прямые контакты образуют единый sidebar без визуально склеенных разнородных панелей.

### Решения по блокам

- **Hero:** тёмный первый экран; заголовок и лид балансируются по сетке главной. Основной CTA не переносится по словам, на mobile сохраняет одну строку и полную ширину.
- **AnchorNav:** компактная тёмная линейка, визуально продолжающая hero; чёткие mono-подписи, тонкие разделители, горизонтальный скролл на mobile, без sticky.
- **ScenarioGrid:** четыре равнозначные карточки 2×2 с номерами, заметными заголовками и читаемыми описаниями. Завершающая тёмная панель объединяет пояснение и CTA. На mobile карточки сохраняют естественную высоту.
- **ChannelsSection:** пять направлений как единая нумерованная система; отдельная колонка индекса, сильное название, спокойное описание и точные разделители. На mobile описание остаётся в колонке названия, без длинных пустых лент.
- **ApproachSection:** матрица принятия решений с усиленной первой колонкой и визуально обозначенным переходом к решению. Итоговый текст оформляется как вывод, выровненный с колонкой решений.
- **KpiSection:** контрастная тёмная секция с четырьмя самостоятельными уровнями метрик, а не копия матрицы подхода. Номера и красные линии показывают систему измерения; пояснение остаётся спокойным.
- **ProcessSection:** компактная таблица с заметной нумерацией и достаточной шириной длинного названия второго этапа. Результат отделён от описания работы. На mobile — лёгкие карточки этапов без принудительной высоты.
- **PricingSection:** две равнозначные карточки бюджета с согласованной нумерацией; дополнительные работы — читаемый список в общей панели; CTA завершает эту композицию.
- **Финальный CTA:** форма остаётся основной, sidebar визуально един и отделён одной линией. Аудит и контакты используют общий тёмный фон; на mobile порядок — форма, аудит, контакты, без пустых промежутков.

Эти принципы применимы к следующим внутренним страницам: сначала определяется тип данных блока, затем выбирается соответствующий визуальный паттерн; одинаковые заголовок и строки не используются как универсальное решение для всех секций.

### Блок 1. Hero

- H1: **Performance-маркетинг под задачи вашего бизнеса**
- Подзаголовок: «Подбираем и объединяем рекламные инструменты, чтобы привлекать целевые обращения, лиды и будущих клиентов, а также управлять стоимостью привлечения и результатами. Связываем кампании с аналитикой и результатами обработки заявок.»
- Дополнительная строка: «Используем собственную аналитику Prostor.»
- CTA: основная «Обсудить привлечение клиентов», дополнительная «Получить аудит рекламы» — обе к `#contact-form`.
- Desktop: тёмный первый экран, привычная композиция героя (шум, дисплейный заголовок Steelfish со stroke-акцентами); mobile — вертикальный стек, кнопки во всю ширину. `TrustMarquee` не выводится (`showMarquee={false}`).
- Источник: `hero` в контент-файле.

### Блок 2. `AnchorNav`

- Содержание: `Задачи · Каналы · Кейсы · Подход · Процесс · Стоимость · FAQ`.
- Desktop: компактная тёмная линейка под hero, визуально продолжает hero; sticky в первой версии не требуется. Mobile: горизонтальный скролл-снап без видимого скроллбара, без горизонтального скролла страницы.
- Только внутристраничные якоря, никаких `href="#"`.
- Фильтрация: пункты `#cases`/`#faq` не рендерятся, пока соответствующие секции скрыты.

### Блок 3. `ScenarioGrid` — `#tasks`

- Заголовок: **Когда бизнесу нужна работа с performance-рекламой**
- Карточки (2×2 desktop / стек mobile, равнозначные, с номерами; некликабельны):

| Ситуация | Описание |
| --- | --- |
| **Нужны целевые обращения** | Определить, какие рекламные инструменты стоит проверить для вашего продукта и аудитории. |
| **Реклама есть, результат не устраивает** | Разобраться, где теряются бюджет и обращения: в настройках рекламных кампаний, предложении, посадочной странице или обработке заявок. |
| **Нужно проверить новое направление** | Протестировать продукт, оффер, географию или аудиторию по заранее согласованным критериям. |
| **Нужно увеличить объём** | Найти возможности роста и оценить, как расширение повлияет на стоимость и качество привлечения. |

- Завершающая тёмная панель блока объединяет пояснение и CTA: «Начинаем с вашей ситуации. Подключать все рекламные инструменты одновременно необязательно.» + CTA «Обсудить мою ситуацию» → `#contact-form`.

### Блок 4. `ChannelsSection` — `#channels`

- Заголовок: **Подбираем инструменты под вашу задачу**
- Пять направлений как единая нумерованная система (колонка индекса, название, описание, точные разделители):

| Направление | Описание |
| --- | --- |
| **Контекстная реклама** | Запускаем и развиваем рекламу в Яндекс Директе с согласованными целями и аналитикой. |
| **Таргетированная реклама** | Настраиваем и ведём рекламу в соцсетях и мессенджерах: подбираем аудитории, тестируем объявления и отслеживаем обращения. |
| **Яндекс Промостраницы** | Создаём и продвигаем статьи в Яндекс Промостраницах, чтобы знакомить аудиторию с продуктом и привлекать заинтересованных пользователей на сайт. |
| **Авито** | Оформляем и продвигаем объявления на Авито и с помощью Авито Ads, тестируем подачу предложений и отслеживаем обращения. |
| **Геосервисы** | Оформляем и продвигаем карточки компании в картах и геосервисах, чтобы клиентам было проще найти и выбрать вас. |

- Без внешних ссылок; названия направлений не кликабельны (разметка под будущие страницы услуг сохранена в компоненте с TODO).

### Блок 5. Кейсы — `#cases` (скрыт)

- Заголовок (готов): **Как мы решали задачи наших клиентов**
- Состав (план): 2–3 кейса с разными сценариями — улучшение существующей рекламы; запуск нового продукта/направления; увеличение объёма; работа с несколькими инструментами.
- Карточка: клиент и отрасль, ключевая цифра, короткое пояснение к цифре (что считали, с чем сравнивали, за какой срок), использованные инструменты (теги), что сделали/изменили, результаты и сроки. Кнопка «Смотреть кейс» — только при наличии реальной страницы кейса; теги инструментов некликабельны; `showAllLink={false}` (архива кейсов нет).
- ⚠️ `items: []` — подтверждённых кейсов нет, секция не выводится (условие `items.length > 0`), пункт «Кейсы» скрыт из `AnchorNav`. Выдумывать данные запрещено — раздел 6.

### Блок 6. `ApproachSection` — `#approach`

- Заголовок: **Как мы определяем, куда направить бюджет**
- Матрица «Что выясняем → Какое решение принимаем» (усиленная первая колонка, обозначенный переход к решению):

| Что выясняем | Какое решение принимаем |
| --- | --- |
| **Цель и экономика продукта** | Какой результат/KPI оцениваем и какую стоимость привлечения рассматриваем как ориентир. |
| **Аудитория и путь до покупки** | Какие точки контакта и рекламные инструменты стоит проверить. |
| **Состояние сайта и обработки заявок** | Что нужно подготовить до запуска или улучшить параллельно. |
| **Доступный бюджет и данные** | С какого набора гипотез начать, чтобы не распылять ресурсы. |
| **Результаты тестов** | Что продолжать, пересматривать, останавливать или расширять. |

- Итоговый текст-вывод (выровнен с колонкой решений): «Не распределяем бюджет поровну между площадками. Сначала определяем приоритеты и критерии проверки, затем корректируем план по результатам.»

### Блок 7. `KpiSection` — `#kpi`

- Заголовок: **Согласовываем показатели до запуска**
- Контрастная тёмная секция, четыре самостоятельных уровня метрик (не копия матрицы подхода; номера и красные линии показывают систему измерения):

| Уровень | Что предлагаем отслеживать |
| --- | --- |
| **Обращения** | Количество лидов, CPL — стоимость обращения, CPO — стоимость заказа. |
| **Качество** | Количество и стоимость квалифицированных обращений по согласованным критериям. |
| **Целевые действия** | CPA — стоимость конкретного согласованного действия, CR — конверсия на выбранном этапе. |
| **Продажи и экономика** | Выручка, стоимость привлечения покупателя, ROMI, ДРР. |

- Спокойное пояснение: «Для каждого проекта выбираем применимые показатели и фиксируем, что именно считаем лидом, целевым обращением и продажей. При необходимости настраиваем аналитику: от базовых целей в Метрике до полноценной сквозной аналитики.»

### Блок 8. Процесс — `#process`

- Заголовок: **От диагностики до регулярной оптимизации**
- Лид: «Пять этапов — от первой диагностики до решения о развитии. Состав и объём работ на каждом этапе фиксируем до старта.» ⚠️ Сейчас зашит в разметку страницы (`lead="…"`), а не в контент-файл — перенести в `processPm` при следующей правке (раздел 6).
- Компактная таблица с нумерацией 01–05 (результат отделён от описания работы; на mobile — лёгкие карточки этапов без принудительной высоты):

## 5. Форма (одна общая на странице)

- **Расположение**: блок 11, якорь `#contact-form`, тёмная секция вместе с футером. Одна форма на всю страницу; отдельные формы в блоках не создаются, все CTA страницы ведут на якорь.
- **Компонент**: `CtaForm` (`stacked`, слот `form`) + `ContactForm` с конфигурацией полей; mock-отправка по существующему паттерну `data-mock-form` (без реальной отправки на сервер).
- **Поля** (все из брифа):

| Поле | Компонент | Обязательность |
| --- | --- | --- |
| Имя | `TextField` (autocomplete="name") | обязательное |
| Контакт и предпочтительный способ связи | `TextField` — одно поле (`contact: 'single'`), посетитель сам пишет телефон/почту/ник и способ связи | обязательное |
| Сайт или название компании | `TextField` (`company`) | необязательное |
| Сценарий/задача | `SelectField` (`scenario`), опции: заголовки карточек `ScenarioGrid` + «Другое» | необязательное |
| Короткое описание задачи | `TextArea` (`messageLabel="Короткое описание задачи"`) | необязательное |
| Статус рекламы | `ToggleGroup` (`statusToggle`): «Реклама уже есть / Планируем запуск / Пока не определились»; выбор одного, по умолчанию не выбрано | необязательное |
| Приложить файл | `FileField` | необязательное |

- **Валидация** (`requiredFields` + `main.ts`): имя и контакт обязательны — пустое значение блокирует отправку, поле получает `.is-error` и текст ошибки; для контакта жёсткий формат не проверяется, но значение не должно состоять только из пробелов; ошибки сбрасываются при вводе; остальные поля без валидации.
- **CTA формы**: одна кнопка — **«Отправить заявку»** (`submitLabel`). Скрытые поля и передача выбранного сценария/карточки в форму не реализуются.
- **После отправки**: существующий mock-паттерн успешного состояния (кнопка/форма), без реальной отправки.
- **Desktop**: форма (3fr) + sidebar с карточкой аудита и прямыми контактами (2fr) в одной сетке, отделён одной линией. **Mobile** (≤1024): стек; ≤768 — порядок «форма → аудит → контакты», кнопки во всю ширину; `FileField` и toggle не ломают раскладку.
- **Юридическая строка**: существующая строка про согласие с политикой обработки персональных данных (страницы политики нет — TODO сохраняется, как в `ContactForm` главной).

## 7. Не входит в первую версию

- Автоматическая передача выбранной карточки сценария в форму.
- Внешние iframe/демо/виджеты (в т.ч. демо аналитики).
- Фрагменты реальных отчётов (даже обезличенные) — только вторая итерация после согласования.
- Кликабельные фильтры/теги кейсов и ссылка «Все performance-кейсы» — только при появлении реальных страниц.
- Отдельные страницы услуг из блока каналов и ссылки на них.
- Sticky-состояние якорной навигации при скролле.
- Визуальная схема «гипотеза → инструмент → бюджет теста → критерий решения» (опционально, вторая итерация).
- SLA в блоке процесса.
- Реальная отправка формы на сервер (mock-отправка как на главной).
