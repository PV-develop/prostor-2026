# План редизайна Performance и развития библиотеки (этап 2)

Утверждённая архитектура работ по визуальным правкам страницы `/services/performance-marketing/`
(ТЗ: «Prostor — визуальные правки страницы Performance-маркетинга») и развитию библиотеки блоков.
Исходная спецификация страницы: `performance-marketing.md`.

Контекст: главная — этап 1 библиотеки; Performance — этап 2; следующие внутренние
страницы собираются из готовых компонентов. Каждое решение оценено с точки зрения
повторного использования.

## Утверждённые решения

| # | Вопрос | Решение |
| --- | --- | --- |
| 1 | Sticky in-page меню | меню в нижней зоне hero; при скролле прилипает под шапкой сверху |
| 2 | Контурное слово в H1 | «ПОД ЗАДАЧИ» (span.h-stroke) |
| 3 | Стрелки между карточками процесса на PM | включить (прямые, между всеми этапами) |
| 4 | Table-вариант `ProcessSection` | сохранить в библиотеке (3-колоночный табличный паттерн) |
| 5 | Движок частиц | новый слой `src/scripts/visuals/`; `initParticles` главной не трогается; возможная унификация — отдельная задача после стабилизации |

## Разметка блоков ТЗ по стратегии

| 4.1 Hero | `ServiceHero` (новый) | новый универсальный; `page`-вариант `HeroMain` удаляется — один hero на тип страницы |
| 4.1 In-page меню | `AnchorNav` | расширение: `sticky`, scroll-spy (красный активный пункт), автоскролл активного пункта на mobile, токен `--anchor-scroll-offset` |

| 4.2 Задачи | `ScenarioGrid` | расширение: `layout: 'cards' \| 'rows'`; rows — две колонки 35/65, нумерованные строки со стрелками и разделителями |

`NumberedCard` — атом «номер / заголовок / описание / нижняя зона с разделителем»
(вынос карточки этапов из `ProcessSection`); стрелки-декорации передаются слотом.

## Правила против дубликатов

- Ссылки-строки с заливкой → `ServiceList` (srow); термин→описание → `InfoRows`;
  нумерованные сценарии → `ScenarioGrid layout='rows'`; 3-колоночная таблица этапов →
  `ProcessSection variant='table'`.
- Одна нумерованная карточка — `NumberedCard` (потребители: `ProcessSection`, `ChannelsSection`).
- Один hero на тип страницы: `HeroMain` (главная) / `ServiceHero` (внутренние).
- Тёмная плашка-выноска — только `NotePlate`.

## Архитектура визуальных пресетов

```
src/scripts/visuals/
  engine.ts            # canvas 2D, DPR≤1.5, rAF sleep/wake, IO-видимость, pointer (fine), reduced-motion → статичный кадр
  presets/
    types.ts           # контракт VisualPreset / PresetScene
    registry.ts        # имя → ленивый импорт пресета
    network.ts         # 'performance-network'
```

- Сборка: частицы появляются вокруг формы → движутся по индивидуальным траекториям →
  собираются в геометрию → медленный дрейф с сохранением формы; без циклов
  разрушения/пересборки.
- Реакция на курсор — только `pointer: fine`, пружинный возврат.
- Бюджет частиц: desktop ~600, mobile ~200; связи — назначенные рёбра (не N²).
- Фолбэк: reduced-motion / нет canvas — статично отрисованная собранная композиция
  (один кадр); тексты и CTA hero от графики не зависят.

## Особенности реализации

- `AnchorNav` остаётся отдельным блоком-сиблингом hero (sticky внутри
  `overflow: hidden` hero невозможен); композиция на странице, `navigationItems`
  в `ServiceHero` не дублируется.
- PM-контент: `eyebrow: 'Performance-маркетинг'`, контур «под задачи»,
  существующие CTA/тексты сохраняются; новые тексты — только явно заданные ТЗ
  (пояснение задач, «Задача канала», метки стоимости).
- Главная страница: визуально не меняется; изменения `ProcessSection`/`initArrows`
  сохраняют идентичную разметку/стили главной (сверка со скриншотами).
- Токены: `--anchor-scroll-offset`, высота шапки для sticky, размеры заголовка
  ServiceHero, параметры карточек — при повторе значений.
